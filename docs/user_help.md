# 配网模型管理工具 - 用户帮助

## 1. 数据库

在【数据库】页面配置 Oracle 用户名、密码、地址、端口和 Service Name。

点击【测试数据库连接】后：

- 连接成功：显示“数据库连接正常”，约 3.5 秒后自动隐藏；
- 连接失败：保留错误提示；
- 连接过程输出在本页面【数据库运行日志】中。

## 2. 模型工作区

选择：

1. 模型类型；
2. 处理方式；
3. G 文件或包含 G 文件的目录；
4. 当前模型需要的专属参数。

点击【运行当前任务】后，页面直接显示任务进度和本次 Console 日志。

## 3. 报告

模型校验/关联预览成功后无需手工导出。

报告自动生成在当前 G 文件/目录 workspace 下：

```text
Distribution_Model_Reports/YYYYMMDD_HHMMSS/
```

其中包括：

- `report.html`
- `report_环网柜汇总.csv`
- `report_设备明细.csv`
- `console.log`

任务完成后可直接点击：

- 【打开本次 HTML】
- 【打开环网柜 CSV】
- 【打开设备 CSV】
- 【打开报告目录】

报告历史最多保存 30 天，超过 30 天的任务目录会自动清理。

## 4. 历史输入路径

程序会记住上一次选择的 G 文件/目录。

若软件启动时发现上一次路径已不存在，会弹出告警，请重新选择有效路径。

## 5. RMU 名称来源

### 使用 p_NameString

直接使用 G XML 中的相关逻辑名称进行数据库匹配。

### 使用环网柜内图上文字

不读取三类设备 XML 自身的 p_NameString 作为匹配依据：

- CBreakerDis：使用环网柜内识别到的图上开关名称；
- ZhaiWaiJieDiDaoZha：逻辑名称 = 配对 CBreakerDis 名称 + `D`；
- BusDis：逻辑名称固定为 `BUS`。

数据库 CODE 必须等于程序最终用于校验的逻辑 p_NameString。

## 6. 模型关联

必须先执行【模型关联预览】并通过校验，才能执行【执行模型关联】。

正式回写前程序会备份原 G 文件，并通过图元类型 + XML ID 唯一定位目标。


## 当前模型关联状态校验

v2.8.0 起，模型校验不仅检查 Oracle 中是否存在期望设备，还检查 G 文件当前是否已经关联模型。

对于每一个 `CBreakerDis`、`ZhaiWaiJieDiDaoZha`、`BusDis`：

1. 读取当前 G 图元 `keyid`；
2. 如果没有 `keyid`，报告为“未关联”，在其它校验全部通过时允许进入关联预览；
3. 如果存在 `keyid`，通过 Oracle 函数反解：
   - 当前设备 ID
   - 当前表号
   - 当前域号
4. 再根据反解出的设备 ID 查询当前设备数据库记录；
5. 读取当前设备的 `combined_id`；
6. 当前模型必须同时满足：
   - 当前设备 ID = 期望设备 ID
   - 当前表号 = 配置表号
   - 当前域号 = 配置域号
   - 当前设备 `combined_id` = 当前唯一 RMU ID
   - 当前 KeyID = 期望 KeyID

全部满足时报告：

```text
模型已关联且正确
处理建议：模型已关联，无需关联
是否需要回写：NO
```

如果 G 图元没有模型：

```text
当前模型状态：未关联
处理建议：需要关联
是否需要回写：YES
```

如果已有 KeyID 但关联错误：

```text
当前模型状态：模型已关联但关联错误
处理建议：禁止自动关联，请检查现有模型
```

程序不会自动覆盖一个已经存在但错误的 KeyID。

### 环网柜唯一性

如果环网柜名称在 `dms_combined_device` 中不是唯一记录，则整个 RMU 直接阻断：

```text
环网柜ID不唯一或环网柜数据库记录无效，请先检查环网柜模型。
```

即使柜内某个图元已有 KeyID，也只能展示当前 KeyID 的反解信息，不能判定其模型正确。

### 数据库设备数量超过 G 图元数量

如果某个 RMU 的设备表记录数大于 G 文件中对应图元数，关联阻断原因统一显示：

```text
一个环网柜下找到了超过设备总数量的设备，请检查数据库模型。
```
